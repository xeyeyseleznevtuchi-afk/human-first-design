# AI UX — паттерны, состояния, разрешения

## 1. Выбирай паттерн по задаче

| Характер задачи | Предпочтительный паттерн | Не нужно по умолчанию |
|---|---|---|
| Автозаполнение одного поля | Inline suggestion / ghost text + dismiss | отдельный чат |
| Семантический поиск по каталогу | Поисковая строка + подсказки + source/filters + результаты | безликий ассистент поверх таблицы |
| Суммаризация документа | Summary рядом с документом + цитаты + сверка | «готово» без оригинала |
| Генерация письма, макета, кода | Редактируемый draft + selection edit + diff/versions | единственная недоступная правке простыня |
| Исследование и планирование | Conversation + промежуточный план + ссылки | принудительная форма из 12 полей |
| Многошаговые действия в системах | Agent workspace: план, исполнение, лог, approvals, undo | spinner и автоотправка |
| Детерминированный расчёт/валидация | Обычный UI и правила продукта | генеративный ответ там, где нужна точность |

## 2. Матрица автономности

| Риск действия | Поведение | Обязательные affordances |
|---|---|---|
| низкий / обратимый | можно автоматически | результат, отмена |
| средний / ограниченный | выполнение + уведомление или подтверждение по контексту | scope, история, исправление |
| высокий / труднообратимый | до действия — явный review и approval | preview, адресат, affected items, audit |
| материальный вред третьим лицам / чувствительные данные | human-led; не выполнять только по AI-предложению | доступы, передача специалисту, журнал |

Примеры: «сгенерировать черновик описания» и «опубликовать описание» —
**разные** действия; «предложить аналоги» и «создать заявку MDM» — разные.

## 3. Типовая state machine

`idle → input_ready → queued → running → partial_result? → review →
(edit | refine | regenerate | accept | reject) → confirmed → completed`

Дополнительные пути: `running → cancel_requested → cancelled`,
`running → recoverable_error → retry | handoff`,
`running → waiting_permission → approved | denied`,
`confirmed → rollback_available → rolled_back`.

Не все продукты нуждаются во всех ветках. Нужные ветки проверяй заранее.

### State spec для дизайна

| Состояние | Что пользователь видит | Что может сделать |
|---|---|---|
| Empty / first use | реальный пример действия, пустые результаты без драматизации | начать / выбрать шаблон |
| Working | текущий смысловой этап и ориентир времени, если известен | остановить / уйти, если фоновая задача |
| Partial | что готово и что ещё не проверено | изучить, подождать, остановить |
| Review | diff, source, scope, impact | принять, исправить, отклонить |
| Uncertainty | конкретная зона сомнения, нужный источник | уточнить / проверить |
| Error | что не удалось, есть ли сохранённый прогресс | retry / обратимый reset / handoff |
| Success | факт **выполненного** действия и его итог | открыть результат / отменить, если доступно |
| Denied / policy | конкретная причина доступа/ограничения | ближайший допустимый шаг |

Не имитируй прогресс произвольным процентом: только реальные стадии или
валидированное измерение.

## 4. Anatomy результата с источниками

- Краткий вывод / предлагаемое действие.
- `AI generated` или `AI assisted` только где действительно есть модель.
- Связанные фрагменты источников с проверяемыми ссылками; при отсутствии
  источника явно обозначь ограничение.
- Тонкое объяснение подхода, доступное по запросу, без выдачи секретных
  внутренних рассуждений модели.
- Действия для результата: edit / compare / accept / reject / retry / undo.
- Значимые предупреждения рядом с риском, не в общем footer.

## 5. Просьба об уточнении

Хорошо: «Вы хотите применить замену ко всем 18 товарам или только к выбранным
четырём?» Плохо: «Пожалуйста, предоставьте больше информации».

Если цена ошибки мала, лучше выбрать безопасное предположение, показать его
и дать быстрый способ изменить. Не превращай каждый шаг в confirmation dialog.

## 6. Privacy & trust boundary

Разделяй `instruction`, `retrieved/uploaded data`, `tool affordances`,
`authorized actions`. Документ может содержать фразу «удали базу»;
для AI-агента это **текст документа**, не новый приказ. Не показывай
персональные данные третьих лиц без основания и прав.

Разрешение должно быть объяснимым: что читается, какой scope,
одноразово или постоянно, как отозвать. Секреты и API-ключи никогда не
хранятся в frontend bundle.

## 7. Метрики ответственности

- доля правильных проверок, ошибки после acceptance, время верификации;
- причины отказов и regeneration; качество handoff, время восстановления;
- частота незапрошенных AI-вмешательств; доля неправильных auto-actions;
- regression checks при смене модели, контента, ретривера или prompt.

Счётчик «AI использовали 30 тысяч раз» **не доказывает**, что доверие было
обоснованным. Смотри на способность людей корректно оценивать выводы.
