# Decision Playbook: какие паттерны разрешены задачей

Перед созданием UI выбери маршрут. Если проект сочетает несколько, проработай
каждую поверхность отдельно, сохраняя единые бренд/токены/терминологию.

## 1. Маршрутизация

| Вопрос | Если «да» | Следующий шаг |
|---|---|---|
| Есть опубликованный или утверждённый экран? | `redesign` | Инварианты, реальный screenshot, data and action audit |
| Сайт рассказывает о бизнесе и ведёт к контакту/заказу? | `marketing` | Смысловая арт-дирекция + авторский контент + конверсионный путь |
| Работа с таблицами, фильтрами, ролями, заявками? | `B2B/product` | Информационная архитектура + 1 рабочий сценарий end-to-end |
| AI предлагает ответ, ранжирование или генерацию? | `ai-flow` | Provenance, confidence без ложных чисел, edit/reject, quality test |
| AI сам вызывает инструменты и меняет внешние системы? | `agent/action` | Scope, authorization, checkpoint, progress, stop, audit trail |
| Нужна только оценка? | `audit` | Read-only. Severity и доказательства без внесения изменений |

## 2. Выбор формы AI взаимодействия

| Задача | Паттерн | Избегать |
|---|---|---|
| Синоним / одно поле / дополнение строки | Inline suggestion | Полноэкранный чат |
| Переписать документ или блок | Редактор с diff и selective accept | Один недоступный для правки чат-ответ |
| Рассмотреть несколько творческих вариантов | Side-by-side сравнение + сохранить лучший | «Единственный правильный» ответ |
| Исследовать неопределённый вопрос | Conversational workspace + source inspector | Необоснованное «готово» |
| Извлечь из документов факты | Сведения + цитата + переход к источнику | Галлюцинированные ссылки |
| Найти запись в каталоге, применить фильтры | Search/filter/table + AI only for semantic intent | Chat-only навигация |
| Отправить заявку/удалить/опубликовать | Plan + preview + permissions + confirmation | Фоновый auto-send |
| Выполнить многошаговую задачу | Agent workspace + этапы, журналы, cancel, checkpoint | Spinner без контекста и отката |

## 3. Матрица риска автономии

Оценить по двум независимым осям: **последствия** и **обратимость**.

| Воздействие | Рекомендуемая модель |
|---|---|
| Нет внешних побочных действий, легко отменить | Подсказка или автоматическое локальное черновое действие |
| Обратимые изменения рабочей области | Явный diff + undo/history, возможен автошаг при доверенных настройках |
| Передача данных/расход денег/изменения прав | Права + предварительный просмотр + подтверждение в точке действия |
| Необратимое/массовое/системно-критичное действие | Явное разрешение, human-led review, dry run, журнал/компенсация |

Подтверждение в UI не заменяет серверных прав, а красивый прогресс —
идемпотентности, аудита и реального отменяемого процесса.

## 4. Карта состояний (не все нужны всем компонентам)

Раздели: `initial`, `empty`, `typing`, `loading`, `streaming`, `partial`,
`success unreviewed`, `reviewed`, `error transient`, `error permanent`,
`permission denied`, `offline`, `cancelled`, `rolled back`, `stale sources`.

На каждом переходе спроси:
- Что видел человек до события? Чем инициировал?
- Что стало истинным **на сервере** и что можно честно сообщить?
- Есть ли понятный следующий шаг, отмена и сохранение ввода?
- Какую роль/источник/разрешение нужно сообщить?

Используй `templates/state-matrix.md`, не выдумывай success для мокапа.

## 5. Проверка на уровне продукта

Верифицируй 3 главные пользовательские задачи end-to-end (одну первичную,
одну с ошибкой, одну с большим объёмом данных). Для AI добавь промпты из
`references/ai-test-cases.md`. Запиши нефункциональные требования: i18n,
WCAG, мобильные режимы, скорость первого meaningful feedback и privacy.

Верифицируй визуально и технически независимо. `Static QA = pass` не
равнозначно `Visual QA = pass` и не гарантирует безопасный backend.
