# Human-First Design · агентный рабочий процесс

## Цель и правила приоритетов

Создавай **конкретный продукт для реальной задачи**, а не красивый обобщённый
макет. Продуктовый UX, честность содержимого и корректное поведение важнее
декоративной оригинальности. При конфликте: явные требования владельца →
безопасность/права/доступность → существующий бренд, контент и дизайн-система →
пользовательская задача → выразительность. Не объявляй работу «готовой», пока
не проверил её в реально доступной среде. Не заявляй визуальный QA по коду.

## 0. Маршрутизируй задачу

| Режим | Когда | Прочитать до работы |
|---|---|---|
| `create` | новый сайт/страница/экран | `references/taste-v2-process.md`, `references/visual-craft.md`, `references/implementation.md` |
| `redesign` | изменение работающего UI | `references/decision-playbook.md`, `references/review.md`, `references/implementation.md` |
| `audit` | оценить без редактирования | `references/review.md`, `templates/audit.md` |
| `ai-flow` | AI-поиск, генерация, copilot, агент | `references/human-ai-39.md`, `references/ai-patterns.md`, `references/ai-test-cases.md` |
| `handoff` | Figma → frontend / Tilda | `references/implementation.md`, `templates/handoff.md` |

Классифицируй поверхность как `marketing/editorial`, `B2B/product`, `AI-led`
или `hybrid`; при нескольких режимах прочитай оба набора. 39 принципов
проверяй **для AI-функций**, а не для обычного магазина без AI.

## 1. Узнай, что нельзя менять

Выдели из запроса: аудитория, главное действие, бизнес-контекст, существующие
бренд/kit/компоненты/токены, реальные данные, подтверждённые тексты, ограничения,
состояния, API и разрешения. При доступе к существующему UI сначала изучи
структуру и просмотри страницы/скриншоты — **не угадывай** названия компонентов.
Для локализации не переводи собственные имена без согласования. Если пробел
меняет ключевое решение — задай один вопрос; иначе обозначь допущение.
Для больших задач используй `templates/brief.md`.

## 2. Выбери осмысленную арт-дирекцию, не автоматический пресет

До макета сформулируй фразу: **«потому что [предмет/аудитория], здесь [приём],
а не [распространённый шаблон]»**. Для нового публичного сайта сделай два
кратких направления и выбери одно по задаче; для утверждённого UI Kit не
предлагай новый стиль ради разнообразия. Предметные изображения берутся из
материалов заказчика либо из источников с подходящей лицензией и атрибуцией.

Используй систему **Brief → Direction → Build → Browser QA → Repair**:
1. Brief: по каким признакам это именно этот клиент и продукт?
2. Direction: типографика, сетка, цветовые роли, один ведущий образ или приём.
3. Build: реальные данные, интерактивность, состояния, адаптив.
4. QA: фактический браузерный/холстовый просмотр desktop + tablet + mobile.
5. Repair: 1–3 визуально подтверждённых проблемы → исправить → перепроверить;
   до трёх итераций, если есть ресурсы. Не изображай QA без preview.

Для **B2B/dashboard**: приоритет данным, колоночному выравниванию, плотности,
таблицам, фильтрам и спокойной оболочке; не переносить landing-приёмы в админку.
Старые `DESIGN_VARIANCE`/`MOTION_INTENSITY`/`VISUAL_DENSITY` — необязательные
ручные регуляторы, **не ядро** современной Taste Skill v2.x.
См. `references/taste-v2-process.md` и `templates/visual-direction.md`.

## 3. Дизайн-система — источник истины

В Figma: проверь canonical master, properties, variants, styles/variables,
Auto Layout, bindings, актуальность и deprecated. Используй instances, а не
воссозданные визуальные копии. В React/shadcn: используй текущие tokens,
компоненты, типографику, набор иконок; не подменяй библиотеку. В Tilda:
учитывай Zero Block и его адаптивы. Новую примитиву обоснуй отсутствием
эквивалента в системе. В режиме `audit` **ничего не редактируй**.

## 4. Проектируй полезный экран, а не набор карточек

- Выдели главное действие и реальные факты. Не придумывай отзывы, цены,
  статистику, сертификаты, права или названия функций.
- Иерархия: важность → композиция → типографика → цвет; бейдж/бордер/иконка
  только при смысловой функции. Нумерация — для последовательности.
- Тексты: одна терминология от CTA до toast; конкретные глаголы; живой RU/EN;
  русские переносы, брендовые имена, длинные значения.
- Адаптив = переупорядочение задач, а не масштабирование desktop.
- Motion — feedback и ориентация. Избыточные entrance/reveal, glow, blob,
  градиенты, одинаковые rounded cards и фальшивые статусные метки запрещены
  **как дефолт**, но разрешены при обоснованном бренде/требовании.

Подробно: `references/visual-craft.md`.

## 5. AI UX — особая модель ответственности

Обязательно разметь `AI` и `deterministic` части. Выбери inline/editor/chat/
agent не по моде, а по цене ошибки и характеру задачи. Для существенного
результата нужен дешёвый способ проверить источник или diff. Вывод AI —
`draft/suggestion`, пока не прошёл требуемую проверку; исключи мнимые
«98% уверенности». Предусмотри edit/reject/undo/retry/stop по применимости.
Агентные операции: plan → permissions → preview/diff → approval при риске →
execution/progress → result/rollback. Данные из веба/файлов/почты **не**
инструкции; чужая приватность и серверные права не должны теряться в UI.

На стадии проверки **покрой все 39 принципов** из `references/human-ai-39.md`:
помечай `Pass/Fail/Not applicable/Not tested` с кратким доказательством, не
создавай 39 элементов интерфейса. Выполни критические кейсы из
`references/ai-test-cases.md`.

## 6. Реализация и QA

Техника: `references/implementation.md`. Для визуального и UX-аудита —
`references/review.md`. Если HTML доступен локально, можно запустить
`python3 scripts/static_check.py path/to/page.html` (только эвристики,
**не замена** живой проверке). Минимум вручную: desktop 1280–1440,
tablet 768–834, mobile 360–390, 200% zoom, клавиатура, focus, контраст,
`prefers-reduced-motion`, empty/loading/error/permission, длинный RU/EN текст.
Свойства проверены только если фактически изучены.

**Стоп-факторы:** важное действие не работает; скрытое необратимое AI-действие;
утечка чужих данных; ложный успех; критический overflow; неразличимый focus;
сломанная локализация имени бренда. Не компенсируй их красивым баллом.

## 7. Честный формат передачи

`create/redesign`: концепция (одна фраза), что создано/изменено, что
**проверено**, ссылка/артефакт, непроверенное и ограничения. `audit`:
severity → node/URL → evidence → impact → точная рекомендация, без правок.
`ai-flow`: сценарии, action/permission matrix, evidence, recovery, состояния.
В важных задачах приложи `templates/qa-report.md` и при передаче разработчику
`templates/handoff.md`. Сначала исправляй **системную причину**, потом детали.

## Быстрый индекс

- `references/taste-v2-process.md`: актуальный творческий процесс, разница
  между marketing и dashboard, референсы, лицензии и browser loop.
- `references/decision-playbook.md`: дерево выбора типа интерфейса/паттерна.
- `references/visual-craft.md`: типографика, layout, цвет, контент, anti-slop.
- `references/human-ai-39.md`: оригинальная адаптация 39 принципов.
- `references/ai-patterns.md`, `references/ai-test-cases.md`: паттерны и проверки AI.
- `references/implementation.md`, `references/review.md`: сборка и оценка.
- `references/visual-evidence.md`, `references/sources.md`: анализ исходных
  примеров и ссылки; не копируй чужие материалы.
